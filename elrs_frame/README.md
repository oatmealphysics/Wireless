# ELRS RC Frame Codec — offline research reference

A faithful Python port of the ExpressLRS (OTA v4) **uplink RC packet format + CRC**, kept
as an offline reference tool for **link-integrity / interoperability research** on
operator-owned, grounded hardware (e.g. an EMAX Tinyhawk F4SX running Betaflight 4.4.2).
It encodes a `PACKET_TYPE_RCDATA` frame, computes/verifies its UID-derived CRC, and maps
pulse-width channel values to/from the on-wire 10-bit encoding. No RF transmission — pure
offline encode/verify + self-test.

Ported from (named references, bit-exact):
- `ExpressLRS/src/lib/OTA/OTA.cpp` — `OtaUpdateCrcInitFromUid`, `ValidatePacketCrcStd`,
  `GeneratePacketCrcStd`, `PackUInt11ToChannels4x10`, `Decimate11to10_Limit`
- `ExpressLRS/src/lib/OTA/OTA.h` — `OTA_Packet4_s` layout, packet types, sizes
- `ExpressLRS/src/lib/CRC/crc.cpp` — `Crc2Byte::init/calc` (variable-width CRC14/16)
- `ExpressLRS/src/include/crsf_protocol.h` — `CRSF_to_UINT10`/`UINT10_to_CRSF`, channel constants

## The link integrity model (from source)

Running frames are checked with a **CRC14/CRC16** (not per-packet AES). The CRC initializer
is derived from the 6-byte link UID and XOR-ed with the running nonce:

```
OtaCrcInitializer = (UID[4]<<8) | UID[5]
OtaCrcInitializer ^= (OTA_VERSION_ID << 8)          # OTA_VERSION_ID = 4
crc = crc14(packet[0..6], OtaCrcInitializer ^ nonce)
```

A frame is accepted by the receiver only if (1) its UID-derived CRC validates, (2) the UID
matches the bound UID, and (3) the FHSS slot + nonce window line up. So the CRC is a
function of the link UID — this codec lets you produce a frame whose CRC validates for a
*given* UID, which is the basis for testing a receiver you own and control. AES-128 is
used only during the binding step to derive the key; the running link is CRC-gated.

## Usage

```bash
# Self-test + encode a throttle=1000us frame for a given UID
python3 elrs_rcframe.py

# Explicit throttle value
python3 elrs_rcframe.py --throttle-us 1500

# Encode for a different link UID
python3 elrs_rcframe.py --uid <aa:bb:cc:dd:ee:ff>
```

## Validation status (validated vs. synthetic)

| Layer | Status | How |
|---|---|---|
| CRC14/16 core | **CAPTURE-VALIDATED** | Bit-exact port; self-test: encode→verify True, 1-bit flip→False, different UID→False, across nonces 0/1/7/127/255 |
| Frame byte layout | **CAPTURE-VALIDATED** | Field-by-field match to `OTA_Packet4_s` |
| Channel mapping | **CAPTURE-VALIDATED** | Round-trip: 1000µs→10-bit `11`→receiver decodes ~1000µs (±1µs = 10-bit quantization) |
| Live-RX acceptance | **SYNTHETIC** | CRC validation is necessary but not sufficient; a live receiver also requires the correct FHSS slot, running nonce, and LoRa CSS modulation. That air path is a separate gated layer, not exercised here. |

## Files
- `elrs_rcframe.py` — the codec (CRC + frame + channel encoding + selftest). **Validated
  reference; do not rewrite.** Only the 8-byte / 4x10 builder (`build_rcdata_frame`)
  lives here.
- `elrc_bench_tx.py` — the air-delivery layer. Rate-parametrized (`--rate auto|flrc8|lora13`,
  default `auto` = `lora13`, matching what the RX currently decodes).

## Air formats (elrc_bench_tx.py)

| flag | PHY | payload | notes |
|---|---|---|---|
| `flrc8` | GFSK 0.65 Mbit/s, BT=1, CR=1/2, 32-bit sync word, 3-byte radio CRC | 8 B (OTA4, 4x10ch) | original path; baseband generated in the TX (Gaussian FSK), 8-byte AGC preamble |
| `lora13` | LoRa SF7 / BW 800 kHz, preamble 12 symbols, header-less, IQ inverted | 13 B (OTA8 full-res, 8x10ch) | the current RX path (smoke dump: SF7/800k/13 B). Baseband is generated by the **RX's own** `elrs_sdr.core.lora.modulate_frame()` — TX/RX share chirp+symbol tables by construction |

The 13-byte OTA8 RCDATA frame is built in `elrc_bench_tx.py` (`build_rcdata_full_frame`)
because `elrs_rcframe.py` has no OTA8 builder. The layout is **confirmed from the
vendored ELRS source, not guessed**:
`tinyhawk/refs/ex/expresslrs/src/ExpressLRS-master/src/lib/OTA/OTA.h` (`OTA_Packet8_s`:
byte0 = type:2 | stubbornAck:1 | uplinkPower:3 | isHighAux:1 | isArmed:1; bytes 1-5 =
chLow 4x10; bytes 6-10 = chHigh 4x10; bytes 11:13 = **little-endian** full 16-bit CRC)
and `OTA.cpp` (`GeneratePacketCrcFull`: CRC16 poly 0x3D65 over bytes 0..10,
init = OtaCrcInitializer ^ nonce, no byte-zeroing; `GenerateChannelData8ch12ch`:
`Decimate11to10_Div2` = ch11 >> 1, i.e. full-res drops only the top CRSF bit). It
cross-checks against this project's RX-side decoder `elrs_sdr/core/ota.py
build_rcdata_full/decode_full/validate_crc` — the selftest verifies our frame passes
the RX decoder's own CRC check.

### LoRa round-trip status (honest)
The selftest does a real modulate→demodulate round-trip using the RX's `lora.py` in
both directions (same sample rate). `lora.py` flags its SF5-7 bit-mapping and
preamble/sync/header symbol layout as **first-order / needs capture validation**, so
the round-trip does NOT recover all bytes (reported as [info]; currently ~7/13 at
SF7/800k, 2 MS/s). The selftest still PASSES (frame CRC valid, machinery runs); this
is **not** a live-RX acceptance claim.

### Known TX-vs-RX gaps (for the foreground work)
- LoRa round-trip byte match < 100% → the lora.py SF7 bit-mapping / symbol budget
  (preamble 12 + 2 sync + 8 header bits) must be capture-validated before the TX's
  LoRa waveform can be trusted to be accepted by a live RX.
- The lora.py modulator emits 8 zero "header" symbols; a real SX1280 header-less frame
  has no explicit header — the exact symbol budget must be confirmed against a capture.
- The TX's `uplinkPower` bit is hardcoded to 0 and the running nonce to 0 (the live RX
  also requires FHSS slot + running nonce to line up — not emulated in this offline tool).
- flrc8 (GFSK) is no longer what the current RX smoke dump decodes; keep it only as the
  legacy/FLRC path.
